The tables below are a historical snapshot comparing tsrs, TypeScript 7 (tsgo) and `bun check` on seventeen projects.
Benchmark CI is disabled. The default-settings table runs each compiler at its own checker count (tsgo 4, tsrs up to one per
core); the `--checkers` 4, 8 and 16 tables run both at the same count. See [the methodology](README.md) for
the commands, pinned projects, hardware and measurement details, and [archived runs](https://github.com/oxc-project/tsrs/tree/94e7305f0f067e9f68570798c0498e03c7e423eb/bench/results) for other thread

## Benchmark: tsrs vs tsgo 7.1.0-dev.20261018.1 vs bun check

Time and peak memory to type-check each project (`-p <project> --noEmit`) on GitHub Actions `ubuntu-latest` (4 vCPU, 16 GB RAM, Linux x86_64, AMD EPYC 7763 64-Core Processor). Median of 10 interleaved runs (3 for tsgo).

- **tsrs**: commit `20355caa1e04`, PGO-optimized `dist` build, built like the npm release binaries.
- **tsgo**: npm `typescript@7.1.0-dev.20261018.1`, the official Go compiler. tsrs ports commit `b85298b6`.
- **bun check**: Bun 1.4.4-canary.1+ed680823c.

Projects: vscode, xstate-main, webpack, mui-docs, Compiler, Compiler-Unions are from [microsoft/typescript-benchmarking](https://github.com/microsoft/typescript-benchmarking), the suite the TypeScript team benchmarks tsgo on; the other 11 are large open-source applications.

### Default settings on 4 vCPUs

No thread flags: tsgo runs 4 checker threads; tsrs runs 4 (its default: all cores up to 16, then half the cores, at most 32; fewer on small projects); bun check runs one thread per core.

### Against bun check at equal thread counts

The tools pick different thread counts by default, so here each one gets the same number (vscode, 64-core machine, 20
runs each):

| threads | tsgo 7.0.2 | tsrs | `bun check` |
| ---: | ---: | ---: | ---: |
| 4 | 9.75 s, 7.43 GiB | 2.43 s, 1.83 GiB | 4.57 s, 1.46 GiB |
| 8 | 6.13 s, 7.99 GiB | 1.35 s, 1.97 GiB | 2.47 s, 1.60 GiB |
| 16 | 4.54 s, 8.67 GiB | 0.81 s, 2.13 GiB | 1.49 s, 1.85 GiB |
| 64 | 4.01 s, 11.58 GiB | 0.44 s, 3.06 GiB | 0.87 s, 2.86 GiB |

tsrs is about 1.9x faster at every thread count; tsrs uses 7-25% more memory. `bun check` follows TypeScript
7.0 and tsrs follows 7.1-dev, so their error counts can differ slightly; each matches its own reference exactly.

[Benchmark methodology](README.md) explains how everything is measured and how to rerun it. The published numbers
use the PGO-optimized release build, which is 7-14% faster than a plain `cargo build --release`.
