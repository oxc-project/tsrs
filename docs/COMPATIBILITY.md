# TypeScript compatibility

The goal is 100% conformance with TypeScript 7. This page records the current evidence and known gaps.

## Conformance

tsrs is a function-by-function port of the Go implementation of TypeScript (`microsoft/TypeScript`, commit
`3e9236361fa9`, TypeScript 7.1.0-beta). The Go code is the spec: any difference from it in diagnostics,
their order, message text or exit code is a tsrs bug, even when tsrs's output looks better. The
[port log](../notes/typescript-623-ports.md) records all 112 commits of the source upgrade, and the
[beta follow-up log](../notes/typescript-7.1-beta-ports.md) records the tag transition. The last published
release, 0.18.0, uses the earlier `b85298b6a81f` pin; 0.19.0 prepares the new pin.

Using the upstream emit sequence, tsrs matches all 13,700 error baselines, 12,998 `.types` and `.symbols` baselines
each, 13,626 JavaScript/declaration baselines, 149 JavaScript maps and 156 source-map records in both Go and canonical
checker histories. Checking-only harness runs have four diagnostic artifacts that disappear with the full sequence.
It has also been run on a large private monorepo. See the [status log](STATUS.md) for conformance details.

CI and release BOLT gates run that complete comparison in both histories and repeat selected upstream scheduling
regressions at 4 and 8 checkers. Every difference, crash, timeout or empty selection fails the gate; unsupported
cases are reported as skips. CI also checks generated compiler sources, SDK freshness, and all existing upstream
client and local API parity cases against both compilers. The Fourslash gate requires at least 4,092 exercised groups
and rejects all failing groups.

[Top repository conformance](../tools/repo-conformance/README.md) compares diagnostics against pinned tsgo on 1,000
popular TypeScript repositories after qualifying changes merge into `main`. Actions reports include diffs and coverage,
and warn about parity differences; incomplete runs fail. The runner is also available locally.
