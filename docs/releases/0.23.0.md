# 0.23.0

tsrs 0.23.0 targets TypeScript 7.1 beta. The TypeScript source pin remains `microsoft/TypeScript@3e9236361fa9`.
This is an unreleased candidate.

The intended package version is `0.23.0-ts7.1.0-beta` for `tsrs` and `@tsrs/wasm`.

## Whole-program type checking in both modes

`oxlint --type-aware --type-check` checks whole tsconfig programs with or without `TSRS_FAST=1` ([#930]). In 0.22.0,
only the fast preset checked files outside Oxlint's selected set, and it skipped type errors in loose files.

```sh
OXLINT_TSGOLINT_PATH=node_modules/.bin/tsrs-lint oxlint --type-aware --type-check
```

- **Files outside the lint selection are checked.** For each tsconfig that the selected files map to, type checking
  covers the files `tsrs --noEmit` would check, including ignored or generated files and declaration files subject
  to compiler options such as `skipLibCheck`. Global diagnostics are reported on the tsconfig.
- **Loose and excluded files keep their type errors.** Files sent by Oxlint that no discovered tsconfig includes
  are checked in an inferred program with tsgolint's fallback options. This restores their type errors under the
  fast preset.
- **Each file's type errors are reported once.** When programs overlap, a selected file is reported by the program
  it maps to; any other file is reported by the first selected configured program eligible to check it.
- **Project references find the right config.** Config discovery follows transitive project references, including
  custom-named configs and deeper or diamond-shaped reference graphs, and preserves inherited compiler options
  ([#934]).

This changes the scope of `--type-check`: selecting only a clean file can fail because another file in the same
tsconfig has a type error. Oxlint's ignore patterns still control lint rules, but do not hide those program type
errors. Checking whole programs can do more work than checking only selected files. The combined run can replace
a separate typecheck when both use the same tsconfigs; overlapping package configs can add work compared with
checking one root config.

## Other changes

- **Platforms.** The release keeps macOS arm64/x64, Linux x64/arm64 (glibc and musl), and Windows x64 packages.
  Windows ARM64 packaging ([#903]) is deferred until its npm package is set up and native release validation passes.
- **Compiler rebuild memory.** Full program rebuilds use fresh per-build allocation regions, fixing worker-arena
  memory growth across repeated rebuilds ([#895]).
- **`no-misused-promises`.** Avoids expensive type expansion for generic callbacks and overloads, skips parameters
  without corresponding arguments, and refreshes the upstream generic-overload baselines ([#907], [#923]).
- **`prefer-optional-chain`.** Reports optional-chain opportunities inside JSX callbacks and refreshes the
  upstream JSX baselines ([#910], [#926]).
- **`no-unnecessary-condition`.** Fixes false positives for unresolved conditional types such as `Awaited<T>`,
  while still reporting conditions whose constraints prove they are always truthy or never nullish ([#911]).
- **`no-unsafe-assignment`.** Fixes false positives for quoted, numeric, and computed object properties
  contextually typed as `unknown`, and reports `any` assignments to JSX props ([#914], [#924]).
- **`prefer-includes`.** Handles escaped backslashes in regular-expression patterns and preserves escaping in
  generated `.includes()` fixes ([#918]).
- **`no-unnecessary-type-assertion`.** Reports assertions that may supply a generic call's inferred type arguments,
  recommending explicit type arguments without an automatic removal fix ([#925]).
- **Maintenance.** Lint baselines live in `crates/tsrs_lint/tests/baselines`; copied Go test sources are removed
  ([#919]).

Supported platforms and known limitations remain listed in the [compatibility table](../COMPATIBILITY.md).
