# 0.24.0

tsrs 0.24.0 targets TypeScript 7.1 beta, with package version `0.24.0-ts7.1.0-beta` for `tsrs` and `@tsrs/wasm`.
The TypeScript source pin remains `microsoft/TypeScript@3e9236361fa9`.

```sh
pnpm add -D tsrs@0.24.0-ts7.1.0-beta
# WebAssembly for Node and browsers:
pnpm add @tsrs/wasm@0.24.0-ts7.1.0-beta
```

## Faster language-server edits

The language server reuses the program after edits that preserve a file's imports, including in projects using
`importHelpers` or `jsx: react-jsx` ([#948], fixing [#946]). Synthetic imports for `tslib` and the JSX runtime no
longer force a full rebuild after every ordinary edit. Each replaced file owns its reused synthetic import nodes.

Edits that change imports still trigger a full rebuild, which remains slower than the pinned Go compiler on the
reported reproduction. The linked PR records edit-latency, instruction and memory measurements for this change.

## Linting and type checking

With `--type-check`, every file is type-checked before any lint rule runs ([#955], fixing [#941]). This prevents
rule type queries from producing spurious global errors on the tsconfig or hiding errors in files checked later.
Errors such as TS2590 retain the file location reported by `tsrs --noEmit`. Checking before rules can add overhead
on larger projects; the linked PR records the measurements.

Headless lint requests over multiple tsconfigs retain less per-program data and reuse common parsing work:

- Each configured program frees its loader allocations when it finishes, instead of retaining every program's
  allocations until the request ends ([#949], fixing [#855]).
- Referenced-project tsconfigs are parsed once per request, avoiding repeated file reads and include-glob expansion
  across programs ([#950]).
- Declaration files are parsed and bound once per file name and parse options, then shared across programs in the
  same request ([#951]).

Shared configs and declaration files stay alive until the request ends. Keeping declarations for reuse can increase
peak memory on some workloads even as it reduces parsing work. The linked PRs record the original series' individual
measurements; these are not measurements of the packaged release.

## Other changes

- Fixes parser panics when JSDoc indentation splits Unicode whitespace, including in example and trailing-tag
  comments ([#940], fixing [#939]). Synthesized declaration comments still use replacement characters where the
  pinned Go compiler emits incomplete UTF-8 bytes.
- Updates Rust dependencies `flate2`, `smallvec` and `ureq` ([#944]).

Packages remain available for macOS arm64/x64, Linux x64/arm64 (glibc and musl), and Windows x64. Windows ARM64
awaits npm setup and a passing native PGO release dry run.

See the [compatibility table](../COMPATIBILITY.md) for supported capabilities and known limitations.
