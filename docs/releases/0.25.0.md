# 0.25.0

tsrs 0.25.0 targets TypeScript 7.1 beta, with package version `0.25.0-ts7.1.0-beta` for `tsrs` and `@tsrs/wasm`.
The TypeScript source pin remains `microsoft/TypeScript@3e9236361fa9`. The type checker is unchanged from 0.24.0.

```sh
pnpm add -D tsrs@0.25.0-ts7.1.0-beta
# WebAssembly for Node and browsers:
pnpm add @tsrs/wasm@0.25.0-ts7.1.0-beta
```

## Windows ARM64

`tsrs` now installs a native binary on Windows ARM64 through the new `@tsrs/win32-arm64` package
(`aarch64-pc-windows-msvc`). Like Windows x64, it is a PGO build trained natively on the conformance suite, the CLI
and the linter, and the release runs the same installed-package CLI and SDK smoke test on it. The instrumented and
final builds link with `rust-lld`, because `link.exe` corrupts LLVM profile data on ARM64.

## Linting and the command line

- Headless lint requests check separate tsconfig programs concurrently on a quarter of the cores, each with its own
  checker pool ([#957], fixing [#956]). Output stays in program order and matches serial runs byte for byte; setting
  `RAYON_NUM_THREADS` keeps the serial path. On a repository with about 40 tsconfigs this cut wall time by roughly a
  third at the same CPU time, with higher peak memory. The linked PR records the measurements.
- Command-line arguments that are not valid UTF-8 report TS6231 like the pinned Go compiler instead of panicking, in
  both `tsrs` and `tsrs-lint` ([#965], fixing [#964]).
- The "not supported" errors for `--init`, `--showConfig` and `--watch` on Windows go to stderr instead of stdout
  ([#967]).

Packages are available for macOS arm64/x64, Linux x64/arm64 (glibc and musl), and Windows x64/arm64.

See the [compatibility table](../COMPATIBILITY.md) for supported capabilities and known limitations.
